Data types

How numbers and characters are stored in binary: negative numbers, binary arithmetic, floating point and bitwise operations. Every tool here has clickable bits, so you can check your working on any question.

1.4.1a

Primitive data types

IntegerA whole number, positive or negative, e.g. -7, 2048.
Real / floatA number with a fractional part, e.g. 3.14, -0.5.
CharacterA single letter, digit or symbol, e.g. 'A', '7', '#'.
StringA sequence of characters, e.g. "Hello", "07700 900123".
BooleanOne of two values: True or False.

Choose the type that suits the data: a phone number is a string (it can start with 0, and you never do arithmetic on it); a price is a real; a count of items is an integer.

1.4.1b

Binary, negative numbers and hexadecimal

Unsigned binary: in 8 bits, the place values are 128, 64, 32, 16, 8, 4, 2, 1, giving 0 to 255.

Sign and magnitudeThe most significant bit is the sign (0 = positive, 1 = negative); the other 7 bits are the size. −45 = 10101101. Range −127 to +127. Drawbacks: two zeros (00000000 and 10000000) and arithmetic doesn't work with normal binary addition.
Two's complementThe MSB has a negative place value: −128, 64, 32, 16, 8, 4, 2, 1. Range −128 to +127, with one zero. To negate a number: flip all the bits and add 1 (or: copy bits from the right up to and including the first 1, then flip the rest). 45 = 00101101 → flip 11010010 → add 1 → 11010011 = −45.
HexadecimalBase 16, digits 0–9 and A–F. Each hex digit is exactly 4 bits (a nibble), so convert by splitting binary into groups of four: 1011 0111 = B7. Used because it is shorter and easier for people to read than binary, with fewer mistakes, and converts to binary easily (e.g. colour codes, memory addresses, MAC addresses).

1.4.1c

Binary addition and subtraction

Add column by column from the right: 0+0=0, 0+1=1, 1+1=0 carry 1, 1+1+1=1 carry 1. If a result needs more bits than are available, an overflow occurs.

To subtract, find the two's complement of the number being taken away, then add it. Ignore any carry out of the leftmost column.

1.4.1d

Floating point and normalisation

Floating point stores a real number as a mantissa and an exponent, both in two's complement: value = mantissa × 2exponent. The mantissa has an imaginary binary point after the first (sign) bit, so its place values are −1, ½, ¼, ⅛, …

Worked example: floating point to denary

Mantissa 01011000, exponent 0011.

  1. Exponent 0011 = +3.
  2. Mantissa is 0.1011000. Move the point 3 places right (left if the exponent is negative): 0101.1000.
  3. 0101.1 = 4 + 1 + ½ = 5.5.

For a negative mantissa, the sign bit is worth −1 (or −8 after moving the point three places): mantissa 10100000, exponent 0010: 101.00000 = −4 + 1 = −3.

Normalisation

A number is normalised when the mantissa starts 01 (positive) or 10 (negative). To normalise, shift the mantissa left until it does, and subtract the number of places shifted from the exponent. Normalising gives the maximum precision for the number of bits, and makes sure each number has only one representation.

Range and precision

With a fixed total number of bits, more bits in the mantissa give more precision; more bits in the exponent give a bigger range. Floating point gives a far bigger range than fixed point but can be less precise, and calculations are slower.

Adding and subtracting floating point numbers

Worked example: 6 + 1.25

  1. 6 = 0.1100000 × 23; 1.25 = 0.1010000 × 21.
  2. Make the exponents the same: shift the mantissa of the smaller one right by 2 and add 2 to its exponent: 0.0010100 × 23.
  3. Add the mantissas: 0.1100000 + 0.0010100 = 0.1110100, exponent 3.
  4. Normalise the result if needed. 0.1110100 × 23 = 111.0100 = 7.25 ✓

To subtract, take the two's complement of the second mantissa (after matching exponents) and add.

1.4.1e

Bitwise manipulation and masks

Logical shiftMoves all bits left or right, filling the gap with 0s. Shifting left n places multiplies by 2n; right n places divides by 2n (for unsigned numbers; bits that fall off the end are lost).
Arithmetic shiftA right shift that keeps the sign bit by copying it into the gap, so negative two's complement numbers stay negative.
AND maskClears bits: where the mask is 0, the result is 0; where it's 1, the bit is kept. Used to check or extract particular bits.
OR maskSets bits: where the mask is 1, the result is 1.
XOR maskToggles (flips) bits: where the mask is 1, the bit is flipped.

1.4.1f

Character sets

A character set is the list of characters a computer can represent, each with a unique binary code.

ASCII

  • Originally 7 bits: 128 characters (extended ASCII uses 8 bits: 256)
  • English letters, digits, punctuation and control codes
  • Codes are in order: 'A' = 65, 'B' = 66; 'a' = 97; '0' = 48
  • ✗ Can't represent other alphabets or emoji

Unicode

  • Uses up to 32 bits per character (UTF-8 uses 1 to 4 bytes; UTF-16 2 or 4)
  • Over a million possible codes, covering all the world's writing systems, symbols and emoji
  • The first 128 codes are the same as ASCII
  • ✗ Text can take more storage
