Data structures

Ways of organising data so it can be stored and processed efficiently. For each structure you need to know how to create it, traverse it, and add and remove data. Every tool below shows the pointers working as you go.

1.4.2a

Arrays, records, lists and tuples

ArrayA fixed-size (static) collection of elements of the same data type, accessed by index. Can have one, two or three dimensions: array board[8,8], then board[2,5] = "Q". A 2D array is like a table (row, column); 3D adds a layer.
RecordA collection of related fields, which can be of different types, e.g. a student record with name (string), age (integer) and enrolled (Boolean). Fields are accessed by name: student.name.
ListA dynamic collection of items that can be of different types; items can be added and removed, so its size changes. Items aren't necessarily stored next to each other in memory.
TupleAn ordered collection of items, possibly of different types, that is immutable: once created, it can't be changed, e.g. (51.5, -0.12) for a fixed location.
array scores[3,4]                  // 3 rows, 4 columns
total = 0
for row = 0 to 2
    for col = 0 to 3
        total = total + scores[row,col]
    next col
next row

Static structures (arrays) have a fixed size set when they are created: simple and fast, but space can be wasted or run out. Dynamic structures (lists, linked lists, trees) grow and shrink as needed, using memory efficiently, but need extra memory for pointers and can be slower to access.

1.4.2b

Stacks and queues

Stack (LIFO)

  • Last in, first out: items are added and removed at the top
  • A top pointer shows the top item
  • push: check not full (else overflow), increment top, store item
  • pop: check not empty (else underflow), return item at top, decrement top
  • peek: return the top item without removing it
  • Uses: the call stack for subroutines, undo, back button, evaluating expressions

Queue (FIFO)

  • First in, first out: added at the rear, removed from the front
  • Front and rear pointers
  • enqueue: check not full, increment rear, store item
  • dequeue: check not empty, return item at front, increment front
  • In a linear queue, spaces freed at the front can't be reused. A circular queue wraps the pointers round: rear = (rear + 1) MOD size
  • Uses: printer queues, keyboard buffers, scheduling processes

1.4.2c

Linked lists

A linked list is a dynamic structure where each node holds data and a pointer to the next node. A start pointer identifies the first node; the last node's pointer is null. Unused nodes are kept in a free list, identified by a free pointer.

  • Traverse: start at the start pointer and follow each pointer until null.
  • Add: take the node at the free pointer and update the free pointer; store the data; find the right place by traversing; set the new node's pointer to the next node, and the previous node's pointer to the new node.
  • Remove: traverse to the node; set the previous node's pointer to the removed node's pointer (bypassing it); add the removed node to the free list.

✓ Items can be inserted or removed without moving any other data — only pointers change. ✗ No direct access by index: to find an item you must traverse from the start; pointers use extra memory.

Try it: an ordered linked list stored in an array

Names are kept in alphabetical order. Watch which pointers change when you add or remove one. −1 means null.

1.4.2d

Graphs

A graph is a set of vertices (nodes) connected by edges (arcs). Graphs can be directed (edges one way) or undirected, and weighted (each edge has a cost, such as a distance) or unweighted. They model networks such as roads, social networks and the web.

Adjacency matrix

  • A 2D array: row = from, column = to; a 1 (or the weight) shows an edge
  • ✓ Fast to check whether an edge exists
  • ✗ Wastes memory for sparse graphs (few edges)

Adjacency list

  • Each vertex stores a list of its neighbours
  • ✓ Memory-efficient for sparse graphs
  • ✗ Slower to check whether a particular edge exists

Traversals: depth-first goes as far as possible along one branch before backtracking (uses a stack); breadth-first visits all neighbours of a node before moving further away (uses a queue).

1.4.2e

Trees and binary search trees

A tree is a connected graph with no cycles, with a root node at the top; each node has children, and nodes with no children are leaves. In a binary tree, each node has at most two children. A binary search tree is ordered: everything in a node's left subtree is smaller, everything in its right subtree is larger, so searching only follows one path (O(log n) if the tree is balanced).

  • Add: start at the root; go left if the new item is smaller, right if larger; repeat until there's an empty place.
  • Remove: a leaf is simply removed; a node with one child is replaced by its child; a node with two children is replaced by its in-order successor (the smallest item in its right subtree).
  • Traversals: pre-order (node, left, right), in-order (left, node, right — gives the items in order), post-order (left, right, node), and breadth-first (level by level).

In the exam

A quick way to write traversals: draw a line round the outside of the tree, starting left of the root. Pre-order: list each node as you pass its left side. In-order: as you pass underneath. Post-order: as you pass its right side.

1.4.2f

Hash tables

A hash table stores data at a position calculated from its key by a hash function, so an item can be found directly in (ideally) one step — O(1) — rather than by searching.

  • A good hash function is quick to calculate and spreads keys evenly over the table. A common one is key MOD tablesize, often with a prime table size.
  • A collision happens when two keys hash to the same position. Resolve it by linear probing (try the next free position, wrapping round) or chaining (each position holds a linked list of items).
  • To search, hash the key and look there; if another item is there, probe onwards until you find it or reach an empty slot. Too many collisions slow it down, so tables are kept partly empty (a low load factor) and may be rehashed into a bigger table.

Try it: hash table with linear probing

11 slots; hash = key MOD 11. Add the numbers 23, 18, 45, 30 and 56 to see collisions.

Going further

Deleting from a linear-probing hash table is tricky: if you just empty the slot, a later search could stop there and miss an item that was probed past it. Real implementations mark the slot as "deleted" (a tombstone) so searches carry on past it.
