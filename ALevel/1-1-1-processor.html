Structure and function of the processor

What's inside a CPU, how data moves between it and memory, the fetch–decode–execute cycle in register-transfer detail, what makes a processor faster, pipelining, and the architectures processors are built on.

1.1.1a

Components of the processor

ALUArithmetic logic unitPerforms arithmetic (add, subtract, multiply, shifts) and logical operations (AND, OR, NOT, XOR, comparisons). Results go to the accumulator, and flags in the status register record things like a zero or negative result, a carry or an overflow.
CUControl unitDecodes instructions and coordinates the processor, sending control signals along the control bus to the other components. It manages the fetch–decode–execute cycle and is driven by the system clock.
RegistersVery small, very fast memory locations inside the CPU, each holding one item being used right now. Some are general-purpose; others have a special purpose (below).

Special-purpose registers

PCProgram counterHolds the address of the next instruction to be fetched. Incremented during each fetch; changed by branch/jump instructions.
MARMemory address registerHolds the address of the memory location to be read from or written to.
MDRMemory data registerHolds the data or instruction just fetched from memory, or waiting to be written to memory. It's a buffer between the CPU and memory.
CIRCurrent instruction registerHolds the instruction currently being decoded and executed, split into the opcode (what to do) and the operand (the data or address to use).
ACCAccumulatorA general-purpose register that holds the results of calculations carried out by the ALU, and data being worked on.

Common mistakes

  • The PC holds an address, not an instruction, and it doesn't "count instructions".
  • The CIR, not the MDR, is where the instruction is decoded. The MDR only holds it briefly on the way.
1.1.1a

Buses

A bus is a set of parallel wires connecting components. Its width is the number of wires, which is the number of bits it can carry at once.

Address busCarries memory addresses from the MAR to memory (and I/O). One-directional. Its width sets how many locations can be addressed: an n-bit address bus can address 2n locations (32 bits → about 4.3 billion).
Data busCarries data and instructions between the CPU, memory and I/O. Bi-directional. A wider data bus moves more bits per transfer.
Control busCarries control signals such as memory read, memory write, clock, interrupt request, bus request/grant and reset. Bi-directional, because components also signal back to the CPU.

In the exam

"Increasing the address bus width" → more memory can be addressed (each extra wire doubles it). "Increasing the data bus width" → more data transferred per cycle, so fewer transfers for large values.

1.1.1a

The fetch–decode–execute cycle

A-Level answers should describe the cycle in terms of registers and buses. Square brackets mean "the contents of".

Fetch

  1. MAR ← [PC] — the address in the PC is copied to the MAR.
  2. The address is sent along the address bus, and the control unit sends a memory read signal on the control bus.
  3. MDR ← [Memory][MAR] — the instruction at that address travels along the data bus into the MDR.
  4. PC ← [PC] + 1 — the PC is incremented (this can happen at the same time as step 3).
  5. CIR ← [MDR] — the instruction is copied into the CIR.

Decode

The control unit decodes the instruction in the CIR, splitting it into opcode and operand.

Execute

The instruction is carried out. For LDA 5: MAR ← 5, then the data at address 5 comes back on the data bus into the MDR, then ACC ← [MDR]. For ADD 6, the ALU adds the fetched value to the ACC. A branch instruction loads a new address into the PC.

1.1.1b

Factors affecting performance

Clock speedThe number of clock cycles per second (Hz). Each step of the FDE cycle is triggered by a clock pulse, so a higher clock speed means more instructions executed per second. Limited by heat: higher speeds use more power and need better cooling.
Number of coresEach core is an independent processor that can run its own FDE cycle, so more instructions can be processed in parallel. The gain depends on the software: tasks must be split into threads that can run independently, and coordinating cores (sharing data, keeping caches consistent) has an overhead. Doubling cores never quite doubles performance.
CacheSmall, very fast memory on the CPU holding frequently or recently used instructions and data. A cache hit avoids a slow fetch from RAM. More cache means more hits, but it's expensive, and bigger caches are slightly slower to search — which is why there are levels: L1 (smallest, fastest, per core), L2, then L3 (largest, often shared between cores).

Going further

Performance also depends on word length (how many bits the CPU processes at once) and the bus widths. Clock speed alone can mislead: a CPU that does more work per cycle can beat a faster-clocked one.

1.1.1c

Pipelining

Pipelining means overlapping the stages of different instructions: while one instruction is being executed, the next is being decoded and the one after that fetched. Each part of the processor stays busy instead of waiting, so more instructions are completed per unit of time (higher throughput) — though each single instruction still takes three stages.

The problem is branches. The processor fetches the next instructions in memory before it knows whether a branch will jump somewhere else. If the branch is taken, those part-processed instructions are wrong and must be thrown away — the pipeline is flushed — which wastes cycles.

1.1.1d

Von Neumann, Harvard and contemporary architectures

Von Neumann

  • One memory holds both instructions and data (the stored program concept)
  • One set of buses shared by both
  • Instructions are fetched and executed one at a time
  • ✓ Simpler and cheaper; memory is used flexibly
  • ✗ Instructions and data can't be fetched at the same time — the Von Neumann bottleneck
  • Used in general-purpose PCs and laptops

Harvard

  • Separate memories for instructions and data
  • Separate buses, so an instruction and data can be fetched at the same time — faster
  • The two memories can be different sizes and types (e.g. instructions in ROM)
  • ✗ More complex; unused space in one memory can't be used by the other
  • Used in embedded systems and digital signal processors

Contemporary processors

Modern CPUs mix the two. Main memory is shared (Von Neumann), but each core has separate L1 caches for instructions and data (Harvard-style), so both can be fetched at once. This is sometimes called a modified Harvard architecture. Modern processors also use pipelining, multiple cores and SIMD instructions that apply one operation to several pieces of data at once.

In the exam

Comparison questions want both sides of each point: "Von Neumann uses one shared bus for data and instructions, whereas Harvard has separate buses, so…"
