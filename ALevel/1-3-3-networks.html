Networks

How data gets from one computer to another: protocols and the TCP/IP stack, DNS, packet switching, and how networks are protected and organised. Follow a web request down and back up the stack, then send packets through a network and break some links.

1.3.3a

Networks, protocols and standards

LANLocal area network: covers a small geographical area (a building or site); the infrastructure is usually owned by the organisation.
WANWide area network: covers a large geographical area, connecting LANs; uses infrastructure leased from telecoms companies. The Internet is the biggest WAN.
ProtocolA set of rules for how devices communicate: data format, addressing, error checking, speed, and so on.
StandardAn agreed specification (often set by bodies such as the IEEE or IETF) that manufacturers follow, so hardware and software from different manufacturers can work together.

Common protocols: HTTP/HTTPS (web pages), FTP (file transfer), SMTP (sending email), POP3/IMAP (receiving email), TCP and UDP (transport), IP (addressing and routing).

1.3.3b

The TCP/IP stack and protocol layering

Network communication is split into layers. Each layer has its own job and protocols, and only talks to the layers directly above and below it. This means each layer can be developed and changed independently (e.g. Wi-Fi replaced by Ethernet without changing HTTP), and the problem is broken into manageable parts.

ApplicationHTTP, FTP, SMTP, DNSProvides services to applications and decides what data to send and in what format.
TransportTCP, UDPSplits data into packets/segments, adds sequence numbers and port numbers (which application), sets up the connection, checks for errors and requests resending of lost packets (TCP).
Network / InternetIPAdds the source and destination IP addresses; routers use these to choose the route for each packet.
LinkEthernet, Wi-FiAdds the MAC addresses of the next device and passes the data across the physical medium as signals.

A socket is an IP address plus a port number, e.g. 203.0.113.10:443. An IP address identifies a device on the internet and can change; a MAC address is the fixed hardware address of a network interface, used to deliver data on the local network.

1.3.3c

The Domain Name System (DNS)

People use domain names; computers need IP addresses. The DNS is a hierarchy of servers that resolves one into the other:

  1. You type www.example.com. The computer checks its own cache; if the address isn't there, it asks its DNS resolver (usually run by the ISP).
  2. If the resolver doesn't have it cached, it asks a root server, which replies with the address of the top-level domain server for .com.
  3. The TLD server replies with the address of the authoritative name server for example.com.
  4. That server returns the IP address. The resolver caches it and sends it back to the computer, which can now connect to the web server.
  5. If the name can't be found, an error is returned.

In the exam

Mention caching: it makes later look-ups faster and reduces load on the DNS servers. Also mention the error returned if the domain doesn't exist.

1.3.3d

Packet switching and circuit switching

Packet switching

  • Data is split into packets, each with a header (source and destination address, sequence number, checksum)
  • Each packet is routed independently by routers and may take a different route
  • Packets may arrive out of order and are reassembled using the sequence numbers; missing or corrupted ones are re-requested
  • ✓ Makes efficient use of the network; routes around broken or busy links
  • ✗ Delays can vary, which is a problem for real-time data

Circuit switching

  • A dedicated path is set up between the two devices for the whole communication (as in old telephone networks)
  • All data follows the same route and arrives in order
  • ✓ Reliable, constant speed, suits real-time voice and video
  • ✗ The links are reserved even when no data is being sent (wasteful); if a link fails, the connection is lost

1.3.3e

Network security and threats

Threats include malware (viruses, worms, trojans, ransomware), hackers gaining unauthorised access, denial of service attacks flooding a server with requests, interception of data in transit, and phishing and other social engineering. Defences include:

FirewallHardware or software that sits between a network and the outside, inspecting packets and blocking or allowing them by rules about IP addresses, port numbers and protocols (packet filtering). Stateful firewalls also track connections, so only replies to requests made from inside are let in.
Proxy serverMakes requests to the internet on behalf of a client, so the client's IP address is hidden. It can filter content (block websites), log activity, and cache frequently visited pages to speed up access and save bandwidth.
EncryptionData intercepted in transit can't be understood without the key, e.g. HTTPS (TLS), WPA2/3 on Wi-Fi. See 1.3.1.

Other measures: strong passwords and two-factor authentication, user access levels, anti-malware software, keeping software patched, and training staff to spot phishing.

1.3.3f

Network hardware, client-server and peer-to-peer

NICNetwork interface card: lets a device connect to a network; has a unique MAC address.
SwitchConnects devices on a LAN; learns which MAC address is on which port and sends each frame only to the right device.
RouterConnects different networks (e.g. a LAN to the Internet) and forwards packets towards their destination using IP addresses and routing tables.
Wireless access pointLets wireless devices connect to a wired network.
Transmission mediaCopper cable (cheap, interference over distance), fibre optic (very fast, long distances, expensive), wireless (convenient, limited range, less secure).

Client-server

  • A central server provides services (files, email, logins, web pages) that clients request
  • ✓ Central backups, security and updates; easy to manage users
  • ✗ Server is expensive and needs expertise; a single point of failure; can bottleneck under load

Peer-to-peer

  • All computers are equal and share resources directly with each other
  • ✓ Cheap, easy to set up, no single point of failure; spreads load (e.g. file sharing)
  • ✗ No central backup or security; files can be hard to find; peers can be slowed down by others using their resources

Going further

TCP is reliable because it uses acknowledgements: the receiver confirms each segment, and anything not acknowledged within a time-out is sent again. UDP doesn't bother, so it is faster but unreliable — ideal for live video calls and games, where a late packet is no use anyway.
