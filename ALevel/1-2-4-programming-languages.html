Types of programming language

Different programming paradigms and why they exist, procedural programming, assembly language using the Little Man Computer, how instructions address memory, and the key ideas of object-oriented programming.

1.2.4a

Programming paradigms

A programming paradigm is a style or approach to programming. Different paradigms exist because different kinds of problem are easier to solve in different ways, and many languages support more than one.

ProceduralA sequence of instructions, organised into procedures and functions that operate on data. Python, C, Pascal.
Object-orientedThe program is built from objects that combine data (attributes) and behaviour (methods). Java, C#, Python.
Assembly (low-level)Mnemonics that map one-to-one to the processor's machine code. LMC, x86, ARM assembly.
DeclarativeDescribes what the result should be, not how to get it — the language works out the steps. Includes functional (Haskell) and logic (Prolog) programming, and query languages such as SQL.
1.2.4b

Procedural languages

Procedural programs are a series of instructions executed in order, using sequence, selection and iteration. Code is broken into procedures and functions (subroutines) that can be called, take parameters and return values. Data is held in variables, which may be local or global.

  • ✓ Easy to follow; suits problems that are naturally a sequence of steps; subroutines allow reuse and decomposition
  • ✗ Data and the code that uses it are separate, so large programs can become hard to manage — global data can be changed from anywhere
1.2.4c

Assembly language and the Little Man Computer

Assembly language uses mnemonics that translate one-to-one into machine code. OCR uses the Little Man Computer (LMC): a simple model with 100 memory locations ("mailboxes" 0–99) and one accumulator.

MnemonicCodeMeaning
ADD1xxAdd the value at address xx to the accumulator
SUB2xxSubtract the value at address xx from the accumulator
STA3xxStore the accumulator at address xx
LDA5xxLoad the value at address xx into the accumulator
BRA6xxBranch (jump) to address xx always
BRZ7xxBranch to xx if the accumulator is zero
BRP8xxBranch to xx if the accumulator is zero or positive
INP901Input a value into the accumulator
OUT902Output the accumulator
HLT000Stop
DAT—Not an instruction: reserves a memory location (optionally with a starting value) and labels it

Labels let you name a location (like a variable) or a line to branch to.

1.2.4d

Modes of addressing memory

The addressing mode tells the processor how to interpret an instruction's operand.

ImmediateThe operand is the actual value to use. LDA #3 loads the number 3. Fast — no memory access needed.
DirectThe operand is the address of the value. LDA 3 loads whatever is stored at address 3.
IndirectThe operand is an address that holds another address, where the value is. Allows access to a wider range of memory than fits in the operand, and is used for pointers.
IndexedThe address used is the operand plus the value in the index register. Increasing the index register moves through consecutive locations — ideal for arrays.

1.2.4e

Object-oriented programming

ClassA template (blueprint) that defines the attributes and methods its objects will have.
ObjectAn instance of a class, with its own values for the attributes. Created by calling the class's constructor (new).
AttributeA piece of data belonging to an object (a variable inside it).
MethodA procedure or function belonging to a class, defining what objects can do.
EncapsulationBundling data and methods together and hiding the attributes (making them private), so they can only be accessed through the class's public methods (getters and setters). This protects data from accidental or invalid changes, and lets the inner workings change without affecting other code.
InheritanceA subclass (child) takes on the attributes and methods of a superclass (parent), and can add its own. Avoids repeating code.
PolymorphismObjects of different classes can be treated the same way, with each responding in its own way — e.g. a subclass overrides a method it inherited. Calling speak() on any pet does the right thing for that pet.
class Pet
    private name
    public procedure new(givenName)
        name = givenName
    endprocedure
    public function getName()
        return name
    endfunction
    public procedure speak()
        print("...")
    endprocedure
endclass

class Dog inherits Pet
    public procedure speak()            // overrides Pet's speak (polymorphism)
        print(getName() + " says Woof")
    endprocedure
endclass

rex = new Dog("Rex")                    // rex is an object (an instance of Dog)
rex.speak()                             // Rex says Woof

Strengths of OOP

  • Models real-world things naturally
  • Encapsulation protects data
  • Inheritance and classes enable reuse
  • Large projects split cleanly between programmers

Weaknesses

  • More planning and design needed up front
  • Can be over-complicated for small, simple programs
  • Programs can be larger and use more memory
