Systems software

How the operating system manages memory, handles interrupts and shares the processor between processes, the different kinds of operating system, and the BIOS, device drivers and virtual machines.

1.2.1a

The need for an operating system

An operating system is a collection of programs that manages the computer's hardware and resources and provides a platform for applications, hiding the complexity of the hardware from users and programmers. Without one, every program would need its own code to drive the hardware.

  • Memory management — allocating RAM to processes and protecting them from each other
  • Processor scheduling — deciding which process uses the CPU and for how long
  • Interrupt handling — responding to events from hardware and software
  • Managing peripherals through device drivers
  • File management, security (user accounts, permissions) and a user interface
1.2.1b

Memory management

The OS must share RAM between many processes, keep them from accessing each other's memory, and cope when there isn't enough. Programs don't need to be stored in one continuous block: they can be split up.

PagingSegmentation
How memory is splitInto equal, fixed-size blocks called pages (e.g. 4 KB)Into variable-size blocks called segments
Based onPhysical divisions — a page may cut through the middle of a routineLogical divisions of the program — e.g. a whole function, module or data structure
TrackingA page table maps each page to a frame in physical memoryA segment table stores each segment's start address and length
Pros / consSimple to manage; no gaps between pages, but the last page may be partly emptySegments match how the program is structured, but variable sizes leave gaps (fragmentation)

Both allow a process's pages or segments to be stored non-contiguously, wherever there's space.

Virtual memory

When RAM is full, the OS uses part of secondary storage as virtual memory. Pages or segments that aren't currently needed are swapped out to disk, and swapped back in when needed. This lets more (or bigger) programs run than RAM alone allows — but secondary storage is far slower, so it slows the computer down.

If RAM is too small, the OS can spend more time swapping pages in and out than doing useful work. This is disk thrashing, and performance collapses.

1.2.1c

Interrupts

An interrupt is a signal to the processor that a device or program needs attention. Examples: a key is pressed, a printer runs out of paper, data arrives from the network, a timer runs out, or a program tries to divide by zero. Each interrupt has a priority.

How interrupts fit into the FDE cycle

  1. The interrupt is sent along the control bus and sets a flag in the interrupt register.
  2. The processor finishes the current FDE cycle — it never stops halfway through an instruction.
  3. At the end of each cycle, it checks the interrupt register. If there's an interrupt with a higher priority than the current task, it services it; otherwise it carries on.
  4. The contents of the registers, including the PC, are saved (pushed onto a stack) so the current task can be resumed.
  5. The address of the interrupt service routine (ISR) is loaded into the PC, and the ISR runs.
  6. When the ISR finishes, the saved values are popped off the stack back into the registers, and the original task carries on exactly where it left off.

If an even higher-priority interrupt arrives while an ISR is running, the ISR itself can be interrupted: its registers are pushed onto the stack too. The stack makes sure everything is resumed in the right order.

1.2.1d

Scheduling

With many processes ready to run and only a few cores, the OS scheduler decides which process runs next. Its aims: keep the CPU busy, give every process a fair share, respond quickly to users, and get as many jobs done as possible — without any process starving (never getting the CPU).

First come first served (FCFS)Processes run in the order they arrive, each to completion. Simple and fair in one sense, but a long job holds everyone else up.
Round robin (RR)Each process gets a fixed time slice (quantum) in turn; unfinished processes go to the back of the queue. Good response for interactive systems, but lots of switching, and no priorities.
Shortest job first (SJF)The waiting process with the shortest total run time goes next, running to completion. Minimises average waiting time, but needs to know (or estimate) run times, and long jobs may starve.
Shortest remaining time (SRT)Like SJF but pre-emptive: if a new process arrives with less time remaining than the current one, it takes over. Even lower average waiting time; long jobs may starve.
Multi-level feedback queues (MLFQ)Several queues with different priorities. Processes move between queues based on their behaviour — e.g. a process that uses its whole time slice drops to a lower queue, so short and interactive processes stay high. Flexible, but complex.

1.2.1e

Types of operating system

DistributedRuns across several computers, sharing the work of a task between them so they appear to the user as one system. Used for very large computations.
EmbeddedBuilt into a device with a dedicated function (washing machine, car control unit). Small, efficient, reliable, with limited resources and a simple or no interface.
Multi-taskingLets one user run several programs at once, sharing CPU time by scheduling (e.g. Windows, macOS).
Multi-userLets many users share one computer's resources at the same time, e.g. a server or mainframe, with scheduling to keep it fair.
Real-timeGuarantees a response within a strict time limit. Used where delay could be dangerous: aircraft autopilots, airbags, industrial control, medical monitors. Often has redundancy built in.
1.2.1f–h

BIOS, device drivers and virtual machines

BIOS

The BIOS (Basic Input/Output System — on modern PCs, UEFI) is the first program to run when the computer is switched on. It's stored in ROM / flash memory. It runs the POST (power-on self-test) to check the hardware, initialises devices, then finds the OS on a storage device and loads it into RAM (the bootstrap). Its settings, such as the boot order, are stored in non-volatile memory.

Device drivers

A device driver is software that lets the OS communicate with a particular piece of hardware. It translates the OS's general instructions into commands specific to that device, so the OS doesn't need to know how every device works. Drivers are specific to both the device and the operating system.

Virtual machines

A virtual machine is software that emulates a computer, so one physical machine can run several operating systems or programs as if they were on separate hardware. Uses:

  • Running a different OS (e.g. Linux on a Windows machine), or old software that needs an old OS
  • Testing software safely in an isolated environment, e.g. analysing malware
  • Running many servers on one physical machine (cloud hosting)
  • Running intermediate code — see below

Intermediate code (e.g. Java bytecode) is code that has been partly translated: it isn't specific to any processor. A process virtual machine (e.g. the Java Virtual Machine) on each platform translates and runs it. The same compiled program can therefore run on any device with the VM — portability — at the cost of running more slowly than native machine code.
