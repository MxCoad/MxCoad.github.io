Web technologies

The languages that make web pages, how search engines find and rank them, and where the processing happens. You need to be able to read and write HTML, CSS and JavaScript, so use the live editor to practise.

1.3.4a

HTML and CSS

HTML (HyperText Markup Language) describes the structure and content of a page using tags. The tags you need to know:

  • <html> the whole page
  • <head> information about the page
  • <title> shown in the browser tab
  • <link> links an external stylesheet
  • <body> the visible content
  • <h1> <h2> <h3> headings
  • <p> paragraph
  • <img src="cat.jpg" alt="…"> image
  • <a href="page.html"> hyperlink
  • <div> a block used to group and style content
  • <ul> <ol> <li> lists and items
  • <form> <input> forms and inputs
  • <script> JavaScript

CSS (Cascading Style Sheets) describes how the page looks. It can be written inline (style="…" on a tag), internally (in a <style> block) or in an external .css file linked with <link rel="stylesheet" href="style.css">.

h1 { color: navy; }                 /* every h1 */
.warning { color: red; font-size: 20px; }   /* class: class="warning" */
#menu { background-color: #eeeeee;          /* id: id="menu" */
        border-style: solid; border-width: 2px; border-color: black;
        width: 300px; height: 100px; font-family: Arial; }

An external stylesheet can be shared by every page, so the whole site looks consistent and can be restyled by changing one file; it's also cached by the browser. A class can be used on many elements; an id should be unique on a page.

1.3.4b

JavaScript

JavaScript adds behaviour: it runs in the browser and can respond to events, check form input and change the page. You may be asked to write JavaScript in the exam:

function check() {
  var age = document.getElementById("age").value;   // read an input
  if (age >= 18) {
    document.getElementById("msg").innerHTML = "Adult";   // change the page
  } else {
    document.getElementById("msg").innerHTML = "Under 18";
  }
}
for (var i = 1; i <= 3; i++) { alert(i); }          // pop-up box
document.write("Hello");                              // write into the page

1.3.4c

Search engine indexing

Search engines can't search the whole web every time someone types a query. Instead they build an index in advance:

  1. Programs called crawlers (spiders, bots) visit web pages and follow the links on each page to find more pages.
  2. For each page, they record the keywords and their positions, and information such as the title, headings and meta data.
  3. This is stored in the index: like the index of a book, it lists each word and the pages it appears on. Pages are revisited regularly to keep it up to date.
  4. When someone searches, the engine looks up the words in the index (fast), then ranks the matching pages, using factors including PageRank.

Site owners can ask crawlers not to visit pages using a robots.txt file.

1.3.4d

The PageRank algorithm

PageRank (developed by Google's founders) ranks a page by the number and quality of pages that link to it. A link is like a vote; a vote from an important page is worth more, and a page that links to many pages shares its vote between them.

PR(A) = (1 − d) + d × ( PR(T1)/C(T1) + … + PR(Tn)/C(Tn) )

  • PR(A) is the PageRank of page A; T1 … Tn are the pages that link to A
  • C(T) is the number of outbound links from page T
  • d is the damping factor, usually 0.85: the probability that a person randomly clicking links keeps clicking rather than going somewhere new

Because each page's rank depends on the others, it is calculated iteratively: start every page at 1, apply the formula to all pages again and again, and stop when the values stop changing.

1.3.4e

Server-side and client-side processing

Client-side

  • Code (usually JavaScript) runs in the user's browser
  • ✓ Instant response with no page reload; reduces load on the server and network traffic
  • ✗ The code is visible and can be changed or turned off by the user, so it can't be trusted; depends on the browser supporting it
  • Uses: checking form input before sending, animations, interactive pages

Server-side

  • Code (e.g. PHP, Python, Node.js) runs on the web server, which sends back the result
  • ✓ Code is hidden and secure; can use the database; doesn't depend on the user's device
  • ✗ Each request adds load to the server and needs a round trip, so it is slower to respond
  • Uses: logins, searching a database, processing payments, final validation

In the exam

Explain why input should be checked on both sides: client-side for a fast, friendly response; server-side because client-side checks can be bypassed, which would let malicious data (such as SQL injection) reach the database.

Going further

Modern sites blur the line: a page can load once and then use JavaScript to fetch just the data it needs from the server in the background (often as JSON), updating part of the page without reloading. This keeps the speed of client-side processing while the server still does the secure work.
