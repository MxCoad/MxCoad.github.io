Software development

The main methodologies used to plan and manage software projects, when each one is the right choice, and how to write and follow algorithms. Exam questions usually give a project and ask you to recommend and justify a methodology.

1.2.3a

The waterfall lifecycle

Requirements→Design→Implementation→Testing→Deployment→Maintenance

Each stage is completed and signed off before the next begins, and produces documentation for the next. If a problem is found, the team can only go back to the previous stage. The user is mainly involved at the start (requirements) and the end (testing and deployment).

Strengths

  • Simple, clear structure with defined milestones and deadlines
  • Thorough documentation
  • Easy to manage, even with large teams

Weaknesses

  • Inflexible: changing requirements are very costly
  • The client doesn't see working software until late
  • Problems with the requirements may only be found during testing

Best for: projects with clear, stable requirements that are unlikely to change, e.g. a well-understood system or one with strict regulations.

1.2.3a

Agile and extreme programming

Agile methodologies develop software iteratively and incrementally: the project is split into short cycles (sprints), each producing a working part of the system that the client reviews. Requirements are expected to change, and the plan adapts. The focus is on working software and collaboration rather than heavy documentation.

Extreme programming (XP)

An agile methodology focused on code quality:

  • Pair programming — two programmers at one computer; one writes, one reviews, and they swap
  • Test-driven development — unit tests are written before the code
  • Short iterations (1–2 weeks) and frequent small releases
  • A customer representative works with the team, providing user stories
  • Continuous integration and refactoring — code is merged and improved constantly
  • A sustainable pace — no regular overtime

Strengths

  • Copes well with changing requirements
  • Client sees working software early and often
  • XP produces high-quality, well-tested code

Weaknesses

  • Hard to predict the final cost and timescale
  • Needs a committed, available client
  • Less documentation, which can make maintenance harder
  • Pair programming costs two programmers' time
1.2.3a

Spiral model and RAD

Spiral model

A risk-driven approach. The project loops repeatedly through four phases, spiralling outwards as the product grows:

  1. Determine objectives for this loop
  2. Identify and resolve risks, often by building prototypes
  3. Develop and test
  4. Plan the next iteration

✓ Excellent for large, complex, high-risk projects, because risks are tackled early. ✗ Expensive; relies on staff skilled in risk assessment; overkill for small projects.

Rapid application development (RAD)

Builds a series of prototypes very quickly, with requirements gathered through workshops and focus groups. Users try each prototype and give feedback; it's refined, often within a strict time limit (timeboxing), until it becomes the final product.

✓ Fast; users heavily involved, so the result meets their needs; good when requirements are unclear. ✗ Focus on the interface can neglect code quality and efficiency; hard to scale to large systems; needs users to be available throughout.

In the exam

Pick out the clues in the scenario: Are the requirements fixed or uncertain? Is the client available? How big and risky is it? Is speed or quality the priority? Then justify your choice and explain why another methodology would be less suitable.

1.2.3c

Writing and following algorithms

You need to be able to write algorithms in pseudocode (OCR's style, or a high-level language) and follow them to work out what they do, using a trace table (a dry run). Each column is a variable or the output; write a value only when it changes.

Try it: trace the algorithm

What does this algorithm do? Fill in the trace table, leaving a cell empty when the value doesn't change.

nums = [4, 9, 2, 7]
max = nums[0]
for i = 1 to 3
    if nums[i] > max then
        max = nums[i]
    endif
next i
print(max)
