Applications generation

Choosing application and utility software, open and closed source, the three kinds of translator, what a compiler actually does at each stage, and how linkers, loaders and libraries turn compiled code into a running program.

1.2.2b

Utilities

Utilities are small programs that perform a specific task to maintain or improve the computer, rather than doing the user's work.

Anti-malwareScans files for known malware signatures and suspicious behaviour; quarantines threats
Disk defragmenterRearranges file fragments on a hard disk so each file is contiguous, reducing head movement and access time
CompressionReduces file sizes for storage or transmission
BackupCopies data (full or incremental) so it can be restored after loss
EncryptionScrambles files or drives so they can't be read without the key
Disk clean-up / file managerRemoves temporary and duplicate files; organises files and folders
1.2.2c

Open source and closed source

Open source

  • Source code is available; users can study, modify and redistribute it (under its licence)
  • Usually free; a community finds and fixes bugs; can be adapted to exact needs
  • ✗ Support may be informal; documentation and polish vary; may need expertise to adapt
  • e.g. Linux, Firefox, LibreOffice, Python

Closed source (proprietary)

  • Only the compiled program is supplied; source code is kept secret
  • Licence restricts copying and modification; usually paid
  • ✓ Professional support, regular updates, often well tested and polished
  • ✗ Can't fix or customise it yourself; tied to the vendor
  • e.g. Microsoft Office, Adobe Photoshop, macOS

In the exam

Answer from the point of view in the question. A user cares about cost, support and features; a developer releasing software cares about income, protecting their work, and community contributions.

1.2.2d

Translators

AssemblerTranslates assembly language into machine code. Each mnemonic translates into one machine code instruction.
CompilerTranslates the whole high-level program into object code in one go. Errors are reported after compilation. The result runs quickly and can be distributed without the source code — but it's platform-specific and must be recompiled after every change.
InterpreterTranslates and executes the program one statement at a time. No object code is produced; it stops at the first error, which helps debugging. Slower to run, and the user needs the interpreter and source code.

Going further

Many modern languages combine both. Java and C# compile to intermediate code (bytecode), which a virtual machine runs — often using a just-in-time (JIT) compiler that compiles frequently used parts to machine code while the program runs.

1.2.2e

Stages of compilation

1. Lexical analysisRemoves whitespace and comments. Splits the source code into tokens (keywords, identifiers, operators, literals). Identifiers are added to the symbol table. Invalid tokens (e.g. an illegal identifier) are reported.
2. Syntax analysisChecks the sequence of tokens against the grammar rules of the language and builds an abstract syntax tree. Syntax errors are reported. Further details such as data types and scope are added to the symbol table.
3. Code generationConverts the syntax tree into object code (machine code, or an intermediate form).
4. OptimisationMakes the code run faster or use less memory without changing what it does — e.g. removing redundant or unreachable code, working out constant expressions at compile time (2 * 3 → 6), simplifying x * 1 to x. It can make compilation slower, and over-aggressive optimisation can introduce bugs.

Try it: watch a compiler at work

Type an assignment statement (letters, numbers, + − * / and brackets), or pick one. Then look at each stage.

1.2.2f

Linkers, loaders and libraries

Libraries are collections of pre-written, pre-tested code (e.g. for maths, graphics or networking) that programs can use.

  • ✓ Saves development time; already tested, so more reliable; written by experts; can be written in another language
  • ✗ May include more than you need; you depend on someone else to fix bugs; a library update can break your program

A linker combines the compiled object code of a program with the object code of any libraries and other modules it uses, resolving references between them, to produce one executable.

Static linking

The library code is copied into the executable. The program is self-contained and won't break if libraries change — but the file is larger, and library fixes need a recompile.

Dynamic linking

The executable only contains references to shared libraries (e.g. DLLs), loaded when the program runs. Smaller files, libraries shared between programs and updated once — but the program fails if the library is missing or an incompatible version.

A loader is part of the operating system. It copies the executable into memory, adjusts memory addresses to where the program has actually been placed (relocation), and loads any dynamically linked libraries it needs, ready to run.
