Input, output and storage

Choosing the right devices for a problem, how magnetic, flash and optical storage actually work, the roles of RAM and ROM, and virtual storage. Exam questions here are nearly always set in a scenario, so practise justifying your choices.

1.1.3a

1.1.3b

Magnetic, flash and optical storage

Magnetic (hard disk drives and tape)

An HDD has spinning platters coated in magnetic material. A read/write head on a moving arm magnetises tiny areas in one of two directions to store 0s and 1s, and reads them back by detecting the direction. The disk is divided into tracks and sectors.

  • ✓ Large capacity and low cost per gigabyte
  • ✗ Moving parts: can be damaged if dropped while running; slower access, because the head must move to the right place (seek time) and wait for the platter to spin round (latency)
  • Magnetic tape is cheaper still, with huge capacity, but has serial access (it must wind to the data), so it's used for backups and archives

Flash (solid state)

Flash memory stores data by trapping electrons in floating-gate transistors arranged in NAND cells. The charge stays without power, so it's non-volatile. Used in SSDs, USB drives and SD cards.

  • ✓ No moving parts: fast, silent, durable, low power, light
  • ✗ Higher cost per gigabyte; each cell has a limited number of write/erase cycles. SSD controllers use wear levelling — spreading writes evenly across cells — to extend their life

Optical

A laser reads a spiral track of pits and lands on the disc surface. Light reflects differently where a pit meets a land, and these changes are read as binary. Recordable discs (CD-R) use a laser to change a dye layer; rewritable discs (RW) use a material that can be switched back.

  • ✓ Very cheap to mass-produce, light and portable — good for distributing data such as films and games
  • ✗ Low capacity (CD ≈ 700 MB, DVD ≈ 4.7 GB, Blu-ray ≈ 25 GB per layer), slow, easily scratched

In the exam

Justify using the characteristics — capacity, speed, portability, durability, reliability, cost — and link each one to the scenario. "SSDs are fast" scores less than "an SSD has no moving parts, so the camera's storage won't be damaged by vibration on the mountain bike".

1.1.3c

RAM and ROM

RAMROM
VolatilityVolatile — contents lost when power is offNon-volatile — contents kept without power
Read / writeRead and writeRead-only (or rarely rewritten, e.g. flash ROM for firmware updates)
HoldsThe OS, programs and data currently in useThe bootstrap loader / BIOS and firmware that must be available at start-up
SizeSeveral gigabytesSmall

A computer needs both: when switched on, RAM is empty, so the instructions to start up and load the operating system must come from ROM. Once running, programs need fast read/write memory, which is RAM.

Going further

There are two main kinds of RAM. DRAM stores each bit as charge in a capacitor that leaks, so it must be refreshed thousands of times a second; it's dense and cheap, and used for main memory. SRAM uses flip-flops, needs no refreshing and is much faster but more expensive — it's used for cache.

1.1.3d

Virtual storage

Virtual storage (storage virtualisation) pools several physical storage devices, possibly in different places, so that they appear to users and software as one single storage device. The user doesn't know or care where the data physically is.

  • Cloud storage (e.g. Google Drive, OneDrive) — files are spread across a provider's data centres but appear as one drive
  • Storage area networks (SANs) and network-attached storage (NAS) — many drives on a network presented as one volume to an organisation's servers

Benefits

  • Easy to add capacity without users noticing
  • Managed centrally: backups and security in one place
  • Data can be duplicated across devices, so one failure doesn't lose it
  • Cloud storage can be accessed from anywhere

Drawbacks

  • Cloud storage needs an Internet connection and is slower than local storage
  • Security and privacy depend on the provider
  • Ongoing costs; complex to set up in-house

Common mistake

Don't confuse virtual storage with virtual memory (using secondary storage as extra RAM — see 1.2.1).
