Algorithms

How to think about problems like a computer scientist, how to design and check algorithms, and the standard searching and sorting algorithms you need to know step by step.

2.1.1

Computational thinking

An algorithm is a sequence of steps that can be followed to solve a problem or complete a task. Computational thinking is the set of skills used to design one.

AbstractionRemoving unnecessary detail from a problem so you can focus on the parts that matter. Example: a London Underground map shows stations and connections, but not real distances, streets or buildings.
DecompositionBreaking a problem down into smaller sub-problems that are easier to understand and solve. Each part can be worked on separately, even by different people. Example: a game splits into graphics, controls, scoring and saving.
Algorithmic thinkingWorking out the steps and their order needed to solve a problem, so that the solution can be followed — and reused for similar problems.

Common mistake

Abstraction isn't "making it simpler" in general — say what detail is being removed and why it isn't needed.

2.1.2

Designing algorithms

Inputs, processes and outputs

Before designing an algorithm, identify its inputs (data going in), processes (what is done to it) and outputs (results). For a program that works out the area of a rectangle: inputs are the width and height; the process is width × height; the output is the area.

Structure diagrams

A structure diagram shows decomposition: the main problem at the top, broken down into smaller sub-problems below it, and so on.

Flowchart symbols

TerminalStart or end of the algorithm
Input / outputData coming in (e.g. from the user) or going out (e.g. printed on screen)
ProcessA calculation or action, e.g. total = total + 1
DecisionA yes/no question with two exits, e.g. Is score > 10?
SubroutineA call to a separate procedure or function

Arrows (lines) show the direction of flow.

Pseudocode

Pseudocode describes an algorithm in a structured, code-like way without worrying about the exact syntax of a programming language. In the exam, OCR uses its Exam Reference Language (ERL); you can answer in ERL, pseudocode or a high-level language such as Python.

score = int(input("Enter score"))
if score >= 50 then
    print("Pass")
else
    print("Try again")
endif
2.1.2

Errors and trace tables

Syntax errorCode that breaks the rules of the language, so it can't be translated or run — e.g. a missing bracket, misspelt keyword or missing colon.
Logic errorThe program runs but gives the wrong result — e.g. using < instead of <=, or dividing by the wrong number.

A trace table is used to follow an algorithm step by step, recording the value of each variable as it changes. It's used to find logic errors and to work out what an algorithm does. Each column is a variable (or the output); add a new row each time a value changes.

2.1.3

Searching algorithms

Linear searchCheck each item in turn from the start until the item is found or the end of the list is reached.
✓ Simple; works on an unsorted list. ✗ Slow on large lists.
Binary searchThe list must be sorted. Check the middle item. If it's the target, stop. If the target is smaller, discard the middle item and everything after it; if bigger, discard the middle item and everything before it. Repeat on the remaining half until found or no items are left.
✓ Much faster on large lists — each check halves the search. ✗ Only works on sorted data.
// Binary search in OCR Exam Reference Language
low = 0
high = items.length - 1
found = false
while found == false AND low <= high
    mid = (low + high) DIV 2
    if items[mid] == target then
        found = true
    elseif items[mid] < target then
        low = mid + 1
    else
        high = mid - 1
    endif
endwhile

2.1.3

Sorting algorithms

Bubble sortGo through the list comparing each pair of adjacent items, swapping them if they're in the wrong order. That's one pass: the largest item "bubbles" to the end. Repeat passes until a pass with no swaps.
✓ Simple to code. ✗ Very slow on large lists.
Insertion sortTake each item in turn (from the second) and insert it into the correct place in the sorted part at the start of the list, shifting bigger items along.
✓ Simple; quick for small or nearly-sorted lists. ✗ Slow on large unsorted lists.
Merge sortDivide the list in half repeatedly until each sub-list has one item. Then merge pairs of sub-lists, putting items in order, until there is one sorted list.
✓ Much faster on large lists. ✗ More complex, and uses extra memory for the sub-lists.
