Programming languages and IDEs

Why there are different kinds of programming language, how code is translated into something the CPU can run, and the tools programmers use to write and debug their code.

2.5.1

High-level and low-level languages

The same instruction — "add two numbers and store the answer" — at three levels:

High-levele.g. Python

total = a + b

Assembly languagelow-level, uses mnemonics

LDA a
ADD b
STA total

Machine codelow-level, binary (illustrative — real CPUs use different codes)

0001 0101
0010 0110
0011 0111
High-level languages
  • Written using English-like keywords, so easier to read, write and debug
  • One statement translates into many machine code instructions
  • Portable: the same code can run on different types of CPU
  • Must be translated before the CPU can run it
  • Examples: Python, Java, C#, JavaScript
Low-level languages
  • Machine code is binary that the CPU runs directly; assembly language uses short mnemonics such as LDA and ADD, each matching one machine code instruction
  • Written for a specific type of CPU, so not portable
  • Hard to write and debug
  • Gives direct control of the hardware and can be very fast and memory-efficient — useful for embedded systems and device drivers

Common mistake

"High-level languages are more powerful" isn't a valid answer. Say what's actually different: easier to understand, portable, one line = many machine code instructions.

2.5.1

Translators: compilers and interpreters

The CPU can only run machine code. A translator converts source code written in a high-level language (or assembly) into machine code.

Compiler

  • Translates the whole program at once
  • Produces an executable file (machine code)
  • Reports all errors at the end; no executable until they're fixed
  • The executable runs quickly — it's already translated
  • Users don't need the compiler or the source code — so the code stays private
  • ✗ Compiling can take time, and must be redone after every change

Interpreter

  • Translates and runs the program one line at a time
  • No executable file is produced
  • Stops at the first error and shows where it is — easy to debug
  • Can run code straight away, even part-finished programs
  • ✗ Runs more slowly, because it's translated every time it runs
  • ✗ Users need the interpreter and the source code

An assembler translates assembly language into machine code.

    2.5.2
    Integrated development environments (IDEs)
    
    
    An IDE is software that provides all the tools a programmer needs to write, test and debug code in one place. Examples include IDLE, Visual Studio Code, Thonny and Replit.
    
    
    
      
    EditorWhere code is written and changed. Features include syntax highlighting (colouring keywords), automatic indentation, auto-complete and line numbers — all making code quicker to write and easier to read.
    
      
    Error diagnosticsHelp find and fix errors: highlighting errors and giving error messages with line numbers. Debugging tools include breakpoints (pause the program at a chosen line), stepping through code one line at a time, and watching the values of variables as it runs.
    
      
    Run-time environmentLets the programmer run and test the program inside the IDE and see its output, without needing to install it or switch to another program.
    
      
    TranslatorA built-in compiler or interpreter, so code can be translated and run with one click.
