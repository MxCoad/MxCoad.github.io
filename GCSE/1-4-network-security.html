Network security

The ways attackers try to get into networks and steal or damage data, and the methods organisations use to stop them. For a game-style introduction, try the Cyber Defence Console first.

1.4.1

Malware

Malware (malicious software) is any software written to cause harm to a computer or its user, or to gain unauthorised access to it.

VirusAttaches itself to a legitimate file or program. It spreads when the infected file is run or copied by a user, and can delete or corrupt data.
WormCopies itself and spreads across a network on its own, without a user having to do anything. It can use up bandwidth and slow networks down.
TrojanPretends to be useful, legitimate software so the user installs it. Once installed it does something harmful, such as opening a "back door" for attackers.
RansomwareEncrypts the user's files and demands payment (a ransom) for the key to unlock them.
SpywareSecretly records what the user does, e.g. logging keystrokes to capture passwords, and sends it to the attacker.

Common mistake

Don't use "virus" to mean all malware. The key difference: a virus needs a user to run or copy a file; a worm spreads by itself.

1.4.1

Social engineering

Social engineering means tricking people into giving away personal information, passwords or access. It works because people are often the weakest point in a network's security — a strong system is no use if someone hands over their password.

PhishingFake emails, texts or websites that pretend to be from a trusted organisation (a bank, a delivery company, the school) to trick people into entering their details or clicking a harmful link.
Pretexting (blagging)Inventing a believable story to get information, e.g. phoning a member of staff and pretending to be from the IT department.
ShoulderingWatching someone enter a password or PIN, e.g. looking over their shoulder at a cash machine.

Signs of a phishing message

  • A sender's address that doesn't match the organisation (e.g. support@paypa1-secure.net)
  • A general greeting like "Dear customer" instead of your name
  • Urgency or threats: "Your account will be closed in 24 hours"
  • Links whose real web address is different from what it claims
  • Spelling and grammar mistakes

Prevention: train staff and users to spot it, never click links in unexpected messages, and contact the organisation directly using details you already trust.

1.4.1

Brute-force and denial of service attacks

Brute-force attack

Using automated software to try every possible password (or a list of common ones) until the right one is found. Short, simple passwords can be cracked in seconds.

Prevention: long, strong passwords; locking the account after a few failed attempts; CAPTCHA tests that software can't pass; two-factor authentication.

Denial of service (DoS) attack

An attacker floods a server (e.g. a website) with so many requests that it can't cope, so legitimate users can't access it. In a distributed denial of service (DDoS) attack, the requests come from thousands of computers at once — often a botnet of computers infected with malware — which makes it much harder to block.

Prevention: a firewall that detects and blocks unusual amounts of traffic; services that filter traffic before it reaches the server.

Common mistake

A DoS attack doesn't usually steal data or get into the system. Its aim is to make a service unavailable.

1.4.1

Data interception and SQL injection

Data interception and theft

Data travelling across a network can be intercepted — for example, by using packet-sniffing software to capture packets on a public Wi-Fi network. If the data isn't protected, the attacker can read passwords, messages or card details.

Prevention: encryption, so intercepted data can't be understood (e.g. websites using HTTPS, encrypted Wi-Fi).

SQL injection

Many websites store data in a database and use SQL to look things up, building the query from what the user types. In an SQL injection attack, the attacker types SQL code into an input box (like a log-in form). If the website doesn't check the input, that code becomes part of the query and is run by the database — letting the attacker log in without a password, or view, change or delete data.

Prevention: validate and sanitise input (check it only contains what's expected), use parameterised queries that treat input as data, never as code, and give the website's database account only the access levels it needs.

1.4.2

Preventing attacks

Penetration testingAn organisation pays authorised experts to attack its own system, to find vulnerabilities so they can be fixed before real attackers find them.
Anti-malware softwareScans files and compares them against a database of known malware. Infected files are quarantined or deleted. It must be updated regularly to recognise new threats.
FirewallMonitors traffic coming into and going out of a network and blocks or allows it based on a set of rules (e.g. blocking certain addresses or ports).
User access levelsDifferent users are given different permissions — what they can read, edit or delete. People only get access to what they need, which limits the damage an attacker or careless user can do.
PasswordsStrong passwords: long, with a mix of upper and lower case letters, numbers and symbols, not a real word or personal detail, and different for each account. Often combined with two-factor authentication.
EncryptionScrambles data using a key so that if it's intercepted or stolen it can't be understood without the key.
Physical securityStops people physically getting to the hardware: locked server rooms, ID cards or biometrics, CCTV and alarms.

Try it: match the threat to the best defence

In the exam

When asked how a method protects a network, say what it does and which threat it stops. "Use a firewall" scores less than "a firewall checks incoming traffic against rules and blocks anything suspicious, which can stop hackers getting in".

Common mistake

A firewall is not anti-malware. A firewall filters network traffic; anti-malware scans files on the computer.
