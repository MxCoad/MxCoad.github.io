Systems architecture

What the CPU does, what's inside it, how it runs instructions, what makes it faster, and where embedded systems fit in. Read each section, try the tools, then test yourself with the exam questions at the end.

1.1.1

The purpose of the CPU

The CPU (central processing unit) is the part of the computer that processes data and instructions. Every program — a game, a web browser, the operating system — is a long list of simple instructions. The CPU's job is to carry them out, one after another, billions of times a second.

It does this by repeating the fetch–execute cycle:

  • Fetch the next instruction from main memory (RAM).
  • Decode it to work out what it means.
  • Execute it — for example, do a calculation, or move data.

While a program is running, its instructions and the data it is using are held in main memory. The CPU fetches them from there.

In the exam

"State the purpose of the CPU" — write: to fetch, decode and execute instructions (or "to process data and instructions"). That's the mark.

Common mistake

"The CPU is the brain of the computer" gets no marks — it doesn't say what the CPU does. And the CPU doesn't store your files; that's secondary storage.

1.1.1

Components of the CPU

You need to know four parts of the CPU and what each one does.

ALUArithmetic logic unit Carries out arithmetic (e.g. addition, subtraction) and logical operations (e.g. AND, OR, NOT, and comparisons such as "is A greater than B?"). Results are stored in the accumulator.
CUControl unit Decodes instructions and sends control signals to the other parts of the CPU and computer, so data moves to the right place at the right time. It manages the fetch–execute cycle.
Cache A small amount of very fast memory inside (or very close to) the CPU. It stores frequently used data and instructions so the CPU doesn't have to fetch them from slower RAM every time.
Registers Tiny, extremely fast storage locations inside the CPU. Each one holds a single item — an address, an instruction or a piece of data — that the CPU is working on right now.

Common mistakes

  • Cache is not the same as RAM. It's much smaller and much faster, and it's part of the CPU.
  • Don't mix up cache and registers: a register holds one value being used right now; cache holds lots of data and instructions that are likely to be needed soon.
  • The control unit doesn't do calculations — that's the ALU.

Going further · grades 8–9

Most CPUs have several levels of cache. Level 1 (L1) is the smallest and fastest, inside each core. L2 is bigger but a little slower. L3 is bigger again and often shared between cores. The CPU checks L1 first, then L2, then L3, and only goes to RAM if the data isn't in any of them.

1.1.1

Von Neumann architecture

Almost all general-purpose computers follow the Von Neumann architecture. Its key idea is the stored program concept: instructions and data are stored together in the same memory, both in binary. The CPU fetches instructions from memory one at a time and executes them.

The four registers you need to know

PCProgram counter Holds the address of the next instruction to be fetched. It goes up by one after each fetch (unless an instruction makes the program jump).
MARMemory address register Holds the address of the memory location that is about to be read from or written to.
MDRMemory data register Holds the data or instruction that has just been fetched from memory, or that is about to be written to memory.
ACCAccumulator Holds the result of calculations carried out by the ALU.

Common mistakes

  • The PC doesn't count how many instructions have run, and it doesn't hold the instruction itself — it holds the address of the next one.
  • MAR = Address, MDR = Data. Remember the middle letter.

Going further · grades 8–9

  • Many CPUs also have a current instruction register (CIR), which holds the instruction while it's decoded and executed.
  • Data travels between the CPU and memory along buses: the address bus carries addresses from the MAR (one way), the data bus carries data and instructions in both directions, and the control bus carries signals from the control unit.
  • Because instructions and data share one memory and one bus, they can't be fetched at the same moment. This limit is called the Von Neumann bottleneck. Some embedded processors use Harvard architecture, which keeps instructions and data in separate memories to get round it.
1.1.1

The fetch–execute cycle

This is how the registers work together. Learn the fetch stage step by step — it's one of the most common exam questions.

Fetch

  1. The address in the PC is copied into the MAR.
  2. The PC is incremented (goes up by 1), so it points to the next instruction.
  3. The instruction stored at the address in the MAR is fetched from memory and copied into the MDR.

Decode

The control unit decodes the instruction in the MDR to work out what needs to be done.

Execute

The instruction is carried out. Depending on the instruction, that might mean the ALU doing a calculation (result in the accumulator), loading data from memory, storing data to memory, or changing the PC to jump to a different instruction. Then the cycle starts again.

1.1.2

CPU performance

Three characteristics of a CPU affect how quickly it can run programs.

Clock speed

The clock speed is the number of fetch–execute cycles the CPU can carry out per second, measured in hertz (Hz). A 3.5 GHz CPU can do about 3.5 billion cycles every second. A higher clock speed means more instructions are executed per second, so programs run faster.

But: a higher clock speed makes the CPU use more power and produce more heat, which needs better cooling.

Cache size

A bigger cache can hold more frequently used data and instructions. That means the CPU has to fetch from slower RAM less often, so it spends less time waiting and performance improves.

But: cache memory is expensive, and after a point, adding more makes less and less difference.

Number of cores

A core is a complete processing unit that can carry out its own fetch–execute cycle. A quad-core CPU has four. More cores means more instructions can be processed at the same time, so the computer can run several programs, or several parts of one program, at once.

But doubling the cores doesn't double the performance, because:

  • the software must be written to use multiple cores
  • some tasks can't be split up, because each step needs the result of the one before
  • the cores have to communicate and coordinate, which takes time

Common mistakes

  • "Clock speed is how fast the computer is" — say how many instructions (cycles) per second.
  • "Twice the cores = twice as fast" — explain why not: software, tasks that can't be split, coordination.
  • Saying cache "stores data" isn't enough — say it's faster than RAM and holds frequently used data, so fewer trips to RAM.

Going further · grades 8–9

The explorer shows a real limit known as Amdahl's law: if part of a task has to be done step by step, that part takes the same time however many cores you add. With 10% step-by-step work, even infinite cores can only make the task 10 times faster. That's why a graphics card (GPU), with thousands of simple cores, is brilliant at tasks that split into many identical pieces, like drawing pixels, but no use for step-by-step ones.

1.1.3

Embedded systems

An embedded system is a computer system built into a larger device, designed to do one dedicated job (or a small set of related jobs).

Typical characteristics

  • Has a dedicated function
  • Often small, low power and cheap to make
  • Very reliable — it may run for years
  • Simple or no user interface
  • Its program is usually stored in ROM (firmware) and rarely changes

Examples

  • Washing machine
  • Microwave oven
  • Central heating thermostat
  • Engine management system in a car
  • Traffic lights
  • Fitness tracker

Compare this with a general-purpose computer, such as a laptop or smartphone, which can run many different programs and do many different jobs.

In the exam

A definition needs both parts: inside a larger device + dedicated function. When asked for examples, use ones from the question's context if it gives one.

Common mistake

A laptop, tablet or smartphone is not an embedded system — it's general-purpose. (It does contain embedded systems, though, such as the controller inside its hard drive.)
